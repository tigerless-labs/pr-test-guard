# PR Test Guard v0.7.0

Version `0.7.0` connects changed Python behavior to direct test and assertion
evidence, then adds an opt-in check that restores compatible base behavior.

## What Changed

- Added a change-evidence record for every changed Python function or method,
  including behavior shapes, related tests, direct-call evidence, direct mock
  replacement, and assertion-flow status.
- Added `PTG007` when a changed function or method has no deterministic direct
  or bounded static call-path test evidence. Evidence propagates through
  resolvable calls between changed functions; direct mock replacements stay
  under `PTG005` to avoid duplicate findings.
- Added bounded intraprocedural result flow through local assignments,
  attributes, and subscripts.
- Added `PTG008` when a real direct call to changed behavior is unobserved or
  reaches only a weak assertion. Existence checks and self-comparisons do not
  count as meaningful constraints.
- Added function-level base-behavior rollback probes to `--deep`. Candidates
  require matching base/PR signatures and direct-call test evidence.
- Added `PTG009` when the PR baseline passes and restoring the base function
  implementation also passes. Collection, import, and syntax failures are
  reported as inconclusive.
- Added `change_units`, `assertion_flows`, and `rollback_probes` to JSON output.
- Extended rule policy configuration to `PTG007`, `PTG008`, and `PTG009`.

## Compatibility

The CLI and Action inputs are unchanged. The three new rules are advisory by
default, so existing consumers may observe additional findings and higher
finding counts. Repositories can set any new rule to `off`, `warn`, or `error`
using the existing rule policy.

Rollback probes use the existing `--deep`, `--test-command`, and `--max-probes`
options. They run in a separate isolated Git worktree and never modify the
checked-out repository.
