# v0.8.0 — Per-test dynamic evidence

PR Test Guard can now connect changed Python lines to the pytest tests that
actually executed them when context-aware coverage data is supplied.

## Highlights

- Added normalized per-test coverage-context ingestion for coverage.py JSON.
- Added runtime execution evidence, exact parameterized test IDs, and
  setup/run/teardown phases to changed-symbol reports.
- Added advisory `PTG010` for deterministically related tests that were
  observed at runtime but did not execute the changed behavior.
- Kept existing XML coverage and PTG001–PTG009 behavior backward compatible
  when `--coverage-contexts` is omitted.
- Added CLI, structured JSON, text, GitHub Summary, and GitHub Action support
  for context-aware coverage evidence.
- Added paired controlled fixtures for runtime mismatch and runtime overlap.

Generate compatible data with pytest-cov and coverage.py dynamic contexts:

```bash
pytest --cov=src --cov-context=test
coverage json --show-contexts -o coverage-contexts.json
pr-test-guard check \
  --base origin/main \
  --coverage coverage.xml \
  --coverage-contexts coverage-contexts.json
```

This remains advisory evidence: execution does not by itself prove behavioral
correctness or assertion adequacy. PTG010 stays inconclusive when paths cannot
be mapped reliably, related tests do not appear in the artifact, contexts are
unknown, or the artifact is incomplete.

## Known limits

- Python/pytest context IDs only.
- Context-aware coverage input is opt-in; PR Test Guard does not instrument the
  target repository automatically.
- No branch-level per-test mapping yet.
- No business-intent correctness inference.
