# PR Test Guard v0.4.0

Version `0.4.0` adds repository-configurable test path recognition so the
checker can handle Python projects whose tests do not follow the built-in
`tests/`, `test_*.py`, or `*_test.py` conventions.

## What Changed

- Added `paths.tests.include` globs to recognize repository-specific test
  layouts such as `spec/` and `*_spec.py`.
- Added `paths.tests.exclude` globs to remove false test classifications;
  excludes take precedence over both configured includes and built-in matches.
- Applied one shared test-path classifier to PTG001, PTG003, PTG004, PTG005,
  related-test discovery, changed-code selection, and text/JSON report counts.
- Removed the reporter's duplicate test-path heuristic so analyzer and output
  classification cannot drift independently.
- Added repository-relative pattern validation, slash normalization, and JSON
  policy output for the effective include/exclude configuration.
- Documented the difference between test classification and `paths.ignore`,
  which remains a post-detection finding filter.

## Configuration

```yaml
paths:
  tests:
    include:
      - "spec/**"
      - "**/*_spec.py"
    exclude:
      - "src/test_support/**"
```

Configured includes extend the built-in conventions. Excludes win when a path
matches both lists or when a built-in test path should be treated as production
code. Patterns are matched against normalized repository-relative paths.

## Compatibility

- Repositories without `paths.tests` configuration retain the previous test
  path behavior.
- Rule actions, `policy.fail_on`, `paths.ignore`, and exit-code behavior are
  unchanged.
- JSON policy output adds `paths.tests.include` and `paths.tests.exclude`
  fields; existing fields remain compatible.
- The GitHub Action needs no new input because its existing `config` input
  already passes repository configuration to the CLI.
