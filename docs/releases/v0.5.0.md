# PR Test Guard v0.5.0

Version `0.5.0` adds explicit source-to-test path mappings for stable test
relationships that cannot be inferred from Python imports, direct calls, test
names, or mock targets.

## What Changed

- Added `related_tests.mappings` configuration with one repository-relative
  `source` glob and one or more `tests` globs per mapping.
- Merged configured candidates with existing deterministic related-test
  discovery instead of replacing inferred relationships.
- Added the inspectable `configured_path_mapping` reason and matched changed
  source paths to related-test output.
- Kept overlapping configured and inferred candidates deduplicated while
  retaining all applicable reasons and changed symbols.
- Supported path mappings for module-level changes even when no changed Python
  class or function symbol can be collected.
- Applied the existing test classifier before configured mappings, so
  `paths.tests.exclude` continues to take precedence.
- Added YAML, JSON, and TOML coverage plus validation for malformed, absolute,
  parent-relative, and empty mapping definitions.
- Documented that mappings provide review context rather than evidence that a
  test ran or sufficiently validates the change.

## Configuration

```yaml
related_tests:
  max_candidates: 5
  mappings:
    - source: "src/payments/**"
      tests:
        - "tests/integration/payments/**"
```

When a changed production path matches `source`, every `test_*` function in a
matched tracked Python test file becomes a related-test candidate. `tests` may
also be a single string. Multiple mappings and multiple matching source paths
are combined deterministically.

Mappings do not suppress PTG001 when the pull request has no test-file change,
do not claim that a candidate test executed, and do not change merge policy.

## Compatibility

- Repositories without `related_tests.mappings` retain the previous candidate
  discovery behavior.
- Existing rule ids, severity policy, exit codes, CLI options, and GitHub Action
  inputs are unchanged.
- Related-test JSON objects now include `matched_sources`; it is an empty list
  for candidates found only through existing symbol relationships.
- Effective policy JSON now includes `related_tests.mappings`, which is an empty
  list when no mappings are configured.
- Human and GitHub summaries label the related-test evidence column as changed
  targets so it can represent either symbols or configured source paths.
