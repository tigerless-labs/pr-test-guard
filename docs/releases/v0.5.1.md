# PR Test Guard v0.5.1

Version `0.5.1` makes repository configuration safer to adopt and easier to
verify before a pull-request analysis runs.

## What Changed

- Added `pr-test-guard validate-config` for configuration preflight without a
  Git repository, base ref, or PR diff.
- Added `--format json` to print the normalized effective configuration for CI
  checks and other automation.
- Reject unknown fields at every supported configuration level, including
  source-to-test mapping entries.
- Suggest nearby supported field names in typo errors, such as
  `max_candidate` -> `max_candidates`.
- Reject ambiguous rule objects that contain both `level` and `action`, or
  neither field.
- Reject rule ids that collide after case normalization.
- Reject empty path patterns and booleans supplied for
  `related_tests.max_candidates`.
- Apply repository-relative path validation consistently to `paths.ignore`,
  `paths.tests`, and `related_tests.mappings`.
- Scope default pytest discovery to the product test suite so `pytest` does not
  collect the nested executable fixture repositories.

## Configuration Validation

Validate an automatically discovered configuration:

```bash
pr-test-guard validate-config
```

Validate a specific file and consume the normalized result as JSON:

```bash
pr-test-guard validate-config \
  --config path/to/.pr-test-guard.yml \
  --format json
```

The command exits `0` for a valid file or valid built-in defaults and exits `2`
for missing, malformed, or semantically invalid configuration.

## Compatibility

- Existing valid YAML, JSON, and TOML configurations retain their behavior.
- Direct boolean rule actions remain supported (`true` means `warn`, `false`
  means `off`).
- Configuration that previously depended on ignored unknown fields, empty path
  entries, or ambiguous rule objects now fails explicitly instead of silently
  falling back to another behavior.
- Detection rules, finding schemas, policy exit codes, and GitHub Action inputs
  are unchanged.
